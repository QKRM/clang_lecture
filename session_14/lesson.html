문자열 비교와 변환

📝 수업 마무리 퀴즈 (15문항) 퀴즈 풀기 내려받기

14차시 강의 노트 - 문자열 비교와 변환 (strncmp, atoi)

이번 차시는 문자열을 비교하고(strncmp), 문자열을 정수로 변환하는(atoi) 함수를 만듭니다. 둘 다 새 메모리를 만들지 않고 입력을 읽어 결과를 계산하는 함수입니다. (문자열 복제 strdup은 11차시에서 다뤘습니다.)

학습 목표

  1. sbs_strncmp로 문자열을 n글자까지 비교할 수 있다.
  2. sbs_atoi로 문자열을 정수로 변환하며 부호·공백을 처리할 수 있다.
  3. 비교 함수의 반환값 규약(음수/0/양수)을 이해하고 올바르게 사용할 수 있다.
  4. (도전) argc/argv로 커맨드라인 인자를 받아 처리할 수 있다.

0부: 들어가며 — 비교와 변환은 어디에 쓰이나

문자열 "비교"가 필요한 곳

컴퓨터는 문자열을 ==로 비교 못 합니다(12차시에서 배웠듯 주소 비교라 소용없음). strncmp는 접두어(prefix)만 비교할 때 특히 유용합니다.

분야예시
버전 비교"v1.2" vs "v1.10" 앞자리만 비교해 같은 메이저 버전인지
명령어 파싱사용자가 입력한 문자열이 "exit"로 시작하는지(strncmp(input, "exit", 4))
파일 매직 넘버파일 앞 몇 바이트로 포맷 판별("PNG", "GIF8" 등)

이 중 "명령어 파싱"과 "버전 비교"는 오늘 도전 과제(명령어 매처, 버전 비교기)에서 직접 만들어 봅니다.

문자열 → 정수 "변환"이 필요한 곳

프로그램 입력은 대부분 문자열로 들어옵니다(커맨드라인 인자, 사용자 입력, 설정 파일). 하지만 계산하려면 정수가 필요합니다. argv[1]은 항상 char *이지 int가 아닙니다.

int main(int argc, char *argv[])
{
    int n = sbs_atoi(argv[1]);   // "42" (문자열) → 42 (정수)
}
분야예시
커맨드라인 인자./calc 3 + 5 → argv[1], argv[3]을 정수로 변환
설정 파일"port=8080"에서 8080 부분을 정수로
사용자 입력나이·개수 등 숫자를 입력받아 계산

규약 하나만 미리 — 비교 함수의 반환값

strcmp 계열(12차시)과 오늘의 strncmp는 모두 같은 규약을 씁니다:

반환값의미
음수s1이 s2보다 사전순으로 앞
0두 문자열이 (본 범위까지) 같음
양수s1이 s2보다 사전순으로 뒤

값 자체(-20인지 -1인지)는 구현마다 다를 수 있고 부호만 의미가 있습니다. 그래서 비교 결과는 항상 == 0, < 0, > 0으로만 판단합니다.

if (sbs_strncmp(a, b, n) == 0)   // 같다  ← 올바름
if (sbs_strncmp(a, b, n) == -1)  // 💥 위험! -20이 나와도 "다르다"인데 놓침

0.5부: 준비 개념 — 커맨드라인 인자 (argc / argv)

오늘 도전 과제(계산기)에서 프로그램 실행 시 붙인 인자를 받아 계산합니다. main의 진짜 시그니처를 처음 씁니다.

int main(int argc, char *argv[])
이름뜻./calc 3 + 5 실행 시
argc인자 개수 (프로그램 이름 포함)4
argv[0]프로그램 이름"./calc"
argv[1]첫 번째 인자"3"
argv[2]두 번째 인자"+"
argv[3]세 번째 인자"5"

예시: 받은 인자를 그대로 출력

#include <stdio.h>

int main(int argc, char *argv[])
{
    int i = 0;

    while (i < argc)
    {
        printf("argv[%d] = %s\n", i, argv[i]);
        i++;
    }
    return (0);
}
$ cc -Wall -Wextra -Werror args.c -o args && ./args hello 42
argv[0] = ./args
argv[1] = hello
argv[2] = 42

핵심 포인트:

  • argv는 전부 문자열(char *)입니다. ./calc 3 + 5의 3도 숫자가 아니라 문자열 "3" → 계산하려면 오늘 만드는 sbs_atoi로 변환해야 합니다. (이 차시에 argv와 atoi를 같이 배우는 이유!)
  • argc 검사부터: 사용자가 인자를 빼먹으면 argv[1]이 없을 수 있음 → if (argc != 4) 같은 개수 검사 없이 접근하면 크래시.
  • argv[2]가 연산자인지 확인할 때는 오늘의 sbs_strncmp 사용 — 두 함수가 한 프로그램에서 만납니다.

1부: sbs_strncmp

s1과 s2를 최대 n글자 비교. 처음 다른 글자의 차이를 반환, 같으면 0. \0을 만나면 멈춤(memcmp와 다른 점).

동작 순서 (코드는 실습에서 직접 작성):

  1. i를 0부터 n 미만인 동안 반복
  2. s1[i]와 s2[i]가 다르거나, s1[i]가 \0이면 → 두 글자의 차이를 반환 (여기서 멈춤)
  3. n글자를 다 봤는데 전부 같았으면 0 반환
strncmp("apple", "apply", 5)
 a  p  p  l  e
 a  p  p  l  y
 =  =  =  =  ≠   → 'e'(101) - 'y'(121) = -20 (음수 = s1이 앞선다)

한쪽이 짧으면? "app" vs "apple" → i=3에서 s1[3]이 \0 → '\0'(0) - 'l'(108) = 음수. 짧은 쪽이 사전순으로 앞이라는 결과가 자연스럽게 나옵니다.

1.5 손으로 추적하기 — strncmp("apple", "apply", 5)

is1[i]s2[i]같은가?진행
0'a''a'같음i++
1'p''p'같음i++
2'p''p'같음i++
3'l''l'같음i++
4'e'(101)'y'(121)다름!101 - 121 = -20 반환

직접 채워볼 것: strncmp("apple", "apply", 4) — 다른 글자에 도달하기 전에 n이 끝나면? (i=4가 되는 순간 i < n 거짓 → 0 반환). strncmp("app", "apple", 5)도 그려보세요.

핵심 포인트:

  • s1[i] == '\0'이면 종료(문자열 끝). 한쪽이 짧으면 그 자리에서 결판
  • unsigned char로 캐스팅해 차이 계산(부호 정확)
  • 반환값의 부호가 중요
memcmp(11차시)는 n바이트를 무조건 보지만, strncmp는 \0에서 멈춥니다.

2부: sbs_atoi

문자열을 정수로 변환합니다. 표준 atoi의 동작 순서를 그대로 따릅니다.

2.1 처리 순서

  1. 선행 공백 건너뛰기 (스페이스, 탭, 개행 등 6종: \t \n \v \f \r)
  2. 부호 +/- 한 개 처리 (-면 부호 변수를 -1로)
  3. 숫자('0'~'9')를 만나는 동안 누적: 결과 = 결과 × 10 + (글자 - '0')
  4. 숫자가 아닌 문자를 만나면 중단, 결과 × 부호 반환

(코드는 실습에서 직접 작성합니다. 공백 판별은 is_space 같은 보조 함수로 빼면 깔끔합니다.)

숫자 누적의 원리

"123"을 왼쪽부터 읽으며 자릿수를 올립니다:

글자 '1':  result = 0 × 10 + 1 = 1
글자 '2':  result = 1 × 10 + 2 = 12
글자 '3':  result = 12 × 10 + 3 = 123

'1' - '0' = 1처럼 문자에서 숫자로는 ASCII 뺄셈(2차시)으로 얻습니다.

2.2 엣지 케이스

입력결과이유
"42"42기본
"-42"-42부호
" 123"123선행 공백
"12ab"12숫자만
"abc"0숫자 없음
"+-5"0부호 한 개만
'5' - '0' = 5(2차시 ASCII). result를 long으로 두면 큰 수에서 조금 안전합니다.

2.3 손으로 추적하기 — atoi(" -42x") 상태 진행표

코드를 짜기 전에 i, sign, result가 한 글자씩 어떻게 바뀌는지 표로 따라가 보세요.

istr[i]단계signresult비고
0' '1.공백 건너뛰기10i++
1' '1.공백 건너뛰기10i++
2'-'2.부호 처리-10i++
3'4'3.숫자 누적-14result=0*10+4
4'2'3.숫자 누적-142result=4*10+2
5'x'4.숫자 아님 → 중단-142루프 탈출

최종 반환값: result * sign = 42 * -1 = -42.

직접 채워볼 것: atoi("+007")과 atoi("abc") — 각각 몇 단계에서 루프가 끝나는지 표로 그려보세요.

2.5부: 함정 두 가지

함정 1 — 비교 결과를 특정 값과 비교하지 마라

0부 규약의 실전판. strncmp의 반환값은 부호만 의미가 있습니다.

if (sbs_strncmp(a, b, n) == -1)   // 💥 구현에 따라 -20이 나오면 놓침
if (sbs_strncmp(a, b, n) < 0)     // ✓ 항상 올바름
if (sbs_strncmp(a, b, n) == 0)    // ✓ "같다" 판단은 == 0

13차시의 NULL 역참조가 검색 함수의 대표 사고라면, == 1/== -1 비교는 비교 함수의 대표 사고입니다.

함정 2 — unsigned char 캐스팅을 빼먹으면 부호가 뒤집힌다

char는 컴파일러에 따라 부호가 있을 수 있습니다. 0x80 이상 바이트(확장 ASCII, UTF-8 한글 등)가 들어오면:

char c = 0xE0;                 // 한글 UTF-8 첫 바이트라면
(int)c                         // -32 (음수로 해석!)
(unsigned char)c               // 224 (올바른 바이트 값)

캐스팅 없이 s1[i] - s2[i]로 빼면 이런 바이트에서 부호가 반대로 나옵니다. 그래서 요구사항이 (unsigned char) 캐스팅 — 10차시 memcmp 때와 같은 이유입니다.

sbs_atoi에도 함정이 있습니다: int 범위(약 ±21억)를 넘는 입력은 표준도 "정의되지 않음". 심화 sbs_atol(advanced.md)이 이 여유를 한 단계 넓히는 연습입니다.

10차시 memcmp부터 오늘까지, 비교 함수가 5개 쌓였습니다.

과제 1: sbs_strncmp

sbs_strncmp.c — 최대 n글자 비교, 처음 다른 글자 차이, 같으면 0.

요구사항:

  • \0을 만나면 종료(문자열 끝)
  • unsigned char로 차이 계산
  • 부호가 정확해야 함
💡 막히면 힌트 보기 (sbs_strncmp 완성 코드)
#include "libsbs.h"

int	sbs_strncmp(const char *s1, const char *s2, size_t n)
{
	size_t	i;

	i = 0;
	while (i < n)
	{
		if (s1[i] != s2[i] || s1[i] == '\0')
			return ((unsigned char)s1[i] - (unsigned char)s2[i]);
		i++;
	}
	return (0);
}
memcmp와 달리 \0에서 멈춥니다. 한쪽이 짧으면 거기서 결판.

과제 2: sbs_atoi

sbs_atoi.c — 문자열을 정수로. 공백 → 부호 → 숫자 순서.

요구사항:

  • 선행 공백 건너뛰기( , \t, \n, \v, \f, \r)
  • +/- 부호 한 개 처리
  • 숫자가 아닌 문자를 만나면 중단
  • 숫자 없으면 0
💡 막히면 힌트 보기 (sbs_atoi 완성 코드)
#include "libsbs.h"

static int	is_space(char c)
{
	return (c == ' ' || c == '\t' || c == '\n'
		|| c == '\v' || c == '\f' || c == '\r');
}

int	sbs_atoi(const char *str)
{
	int		i;
	int		sign;
	long	result;

	i = 0;
	sign = 1;
	result = 0;
	while (is_space(str[i]))
		i++;
	if (str[i] == '+' || str[i] == '-')
	{
		if (str[i] == '-')
			sign = -1;
		i++;
	}
	while (str[i] >= '0' && str[i] <= '9')
	{
		result = result * 10 + (str[i] - '0');
		i++;
	}
	return ((int)(result * sign));
}

엣지 케이스 (꼭 테스트):

"42"→42  "-42"→-42  "  +7"→7  "12ab"→12
"abc"→0  ""→0  "+-5"→0  "\t-99x"→-99
is_space 보조 함수를 만들면 깔끔합니다. result를 long으로 두면 큰 수에 조금 안전.

  3. strncmp를 char로 비교하면 왜 부호가 뒤집힐까? (0x80 이상 바이트가 음수)
  4. if (strncmp(a, b, n) == -1)이 위험한 이유는? (반환값은 부호만 의미. 강의노트 2.5부)
  5. atoi(itoa(n)) == n은 항상 성립할까? (itoa는 11차시 — 서로 반대 방향 변환)

	return (c == ' ' || c == '\t' || c == '\n'
		|| c == '\v' || c == '\f' || c == '\r');

{

	int		sign;
	long	result;

	i = 0;
	sign = 1;
	result = 0;
	while (is_space(str[i]))
		i++;
	if (str[i] == '+' || str[i] == '-')
	{
		if (str[i] == '-')
			sign = -1;
		i++;
	}
	while (str[i] >= '0' && str[i] <= '9')
	{
		result = result * 10 + (str[i] - '0');
		i++;
	}
	return ((int)(result * sign));
}

#include "libsbs.h"
#include <stdio.h>

/* 도전 2 예시 답안: '.'로 구분된 버전 문자열을 부분별로 sbs_atoi 변환해 비교한다. */
static int	next_part(const char *s, int *idx)
{
	int	start;
	int	value;

	start = *idx;
	while (s[*idx] && s[*idx] != '.')
		(*idx)++;
	value = sbs_atoi(s + start);
	if (s[*idx] == '.')
		(*idx)++;
	return (value);
}

static int	compare_version(const char *a, const char *b)
{
	int	ia;
	int	ib;
	int	va;
	int	vb;

	ia = 0;
	ib = 0;
	while (a[ia] || b[ib])
	{
		va = next_part(a, &ia);
		vb = next_part(b, &ib);
		if (va != vb)
			return (va - vb);
	}
	return (0);
}

int	main(void)
{
	char	*v1;
	char	*v2;
	int		cmp;

	v1 = "1.2.3";
	v2 = "1.10.0";
	cmp = compare_version(v1, v2);
	if (cmp < 0)
		printf("%s < %s\n", v1, v2);
	else if (cmp > 0)
		printf("%s > %s\n", v1, v2);
	else
		printf("%s == %s\n", v1, v2);
	return (0);
}
