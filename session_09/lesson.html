9차시 강의 노트 - 헤더 파일 + 문자 분류 함수 구현

오늘부터 libsbs를 직접 만듭니다. 표준 C 라이브러리에 있는 함수들(isalpha, toupper 등)을 우리 손으로 똑같이 구현합니다. 그 전에, 함수가 많아질 때 코드를 정리하는 도구인 헤더 파일을 먼저 배웁니다.

학습 목표

  1. 전처리기(#)가 컴파일 전에 무엇을 하는지 설명할 수 있다.
  2. 헤더 파일(.h)의 역할과 "선언/정의 분리"를 설명할 수 있다.
  3. #include "libsbs.h"로 직접 만든 헤더를 포함하고 <>와 ""의 차이를 안다.
  4. 인클루드 가드(#ifndef / #define / #endif)가 왜 필요하고 어떻게 동작하는지 안다.
  5. ASCII 범위 판별로 문자 분류·변환 함수 7개를 구현할 수 있다.

0부: 전처리기란? (먼저 큰 그림)

C 코드를 컴파일하면 사실 여러 단계를 거칩니다(1차시). 그 맨 처음 단계가 전처리(preprocess) 입니다.

소스(.c) → [전처리] → [컴파일] → [어셈블] → [링크] → 실행 파일
              ↑
        #으로 시작하는 줄을 처리

#으로 시작하는 줄(#include, #define, #ifndef …)은 전처리기 지시문입니다. 진짜 컴파일이 시작되기 전에 전처리기가 이들을 처리해 순수한 C 코드로 바꿉니다.

  • #include <stdio.h> → 그 자리에 stdio.h 파일 내용을 그대로 붙여넣기
  • #define PI 3.14 → 이후 나오는 PI를 전부 3.14로 글자 치환
핵심: 전처리기는 똑똑한 게 아니라 단순한 복사·치환 기계입니다. 이 사실을 알면 헤더와 인클루드 가드가 쉽게 이해됩니다.

1부: 헤더 파일이란?

1.1 선언과 정의의 분리

두 개념을 구분해야 합니다.

용어뜻비유
선언(declaration)"이런 함수가 있다"고 이름·매개변수·반환형만 알림식당 메뉴판 (이름·가격만)
정의(definition)함수의 실제 내용(본문)주방 (실제 요리)

4차시에서는 프로토타입(선언)과 함수 본문(정의)을 한 파일에 뒀습니다. 함수가 많아지면 선언은 헤더 파일(.h)에 모으고, 정의는 소스 파일(.c)에 나눕니다.

/* libsbs.h — 선언만 모음 (메뉴판) */
int   sbs_isalpha(int c);
int   sbs_toupper(int c);
/* sbs_isalpha.c — 정의(주방) */
#include "libsbs.h"        // 메뉴판을 가져옴

int sbs_isalpha(int c)
{
    /* ... 실제 내용 ... */
}

1.2 왜 나누나? — 실제 빌드 흐름

C 프로그램은 보통 여러 .c 파일로 나뉩니다. 각 .c는 따로 컴파일되어 .o(오브젝트 파일)가 되고, 마지막에 링크로 합쳐집니다.

main.c         ─컴파일→ main.o ┐
sbs_isalpha.c  ─컴파일→ sbs_isalpha.o ├─링크→ 실행 파일
sbs_toupper.c  ─컴파일→ sbs_toupper.o ┘

문제: main.c가 sbs_isalpha를 호출하려면 그 함수가 "어떻게 생겼는지"(선언)를 알아야 합니다. 하지만 정의는 다른 파일(sbs_isalpha.c)에 있습니다.

해결: 선언을 헤더에 모아두고, 그 함수를 쓰는 모든 .c가 #include로 헤더를 가져옵니다. 그러면 각 .c는 선언만 보고 컴파일되고, 실제 연결은 링크 단계에서 됩니다.

  • 여러 .c가 같은 함수를 써도 헤더 하나만 #include하면 됨
  • 함수 목록(API)을 헤더만 보고 파악 가능
  • 16차시에서 libsbs.h 하나로 전체 라이브러리를 묶습니다

1.3 #include "..." vs <...>

#include <stdio.h>     // 시스템 헤더 — 표준 경로에서 찾음
#include "libsbs.h"    // 내 헤더 — 현재 폴더에서 먼저 찾음
형식찾는 위치용도
<stdio.h>시스템 표준 경로표준 라이브러리 (남이 만든 것)
"libsbs.h"현재 디렉토리 우선내가 만든 헤더
외우는 법: 꺾쇠 < >는 "남의 것", 큰따옴표 " "는 "내 것". 내가 만든 libsbs.h는 항상 "libsbs.h".

2부: 인클루드 가드 (중복 포함 막기)

2.1 중복 포함은 왜 생기나?

#include는 "파일 내용 붙여넣기"입니다(0부). 그런데 여러 헤더가 서로를 포함하면, 같은 헤더가 두 번 붙여넣어질 수 있습니다.

a.c
 ├ #include "libsbs.h"     ← 1번 붙여넣음
 └ #include "util.h"
     └ #include "libsbs.h" ← util.h 안에서 또 붙여넣음 (2번째!)

결과: int sbs_isalpha(int c); 같은 선언이 두 번 들어가 "중복 선언" 에러가 날 수 있습니다. 작은 프로젝트에선 안 보이다가 커지면 꼭 터집니다.

2.2 인클루드 가드로 방어

헤더 전체를 아래 틀로 감쌉니다.

#ifndef LIBSBS_H      // "LIBSBS_H가 아직 정의 안 됐으면" 아래를 포함
# define LIBSBS_H     // LIBSBS_H를 정의 (표시를 남김)

/* ── 함수 프로토타입들 ── */
int   sbs_isalpha(int c);
int   sbs_isdigit(int c);
int   sbs_isalnum(int c);
int   sbs_isascii(int c);
int   sbs_isprint(int c);
int   sbs_toupper(int c);
int   sbs_tolower(int c);

#endif                // 여기까지가 #ifndef의 범위

2.3 동작을 단계로 추적

전처리기 입장에서 따라가 봅니다.

  • 첫 번째 #include "libsbs.h": LIBSBS_H가 정의 안 됨 → #ifndef 통과 → 내용 포함 + LIBSBS_H 정의됨(표시 남김)
  • 두 번째 #include "libsbs.h": 이미 LIBSBS_H가 정의됨 → #ifndef 거짓 → #endif까지 통째로 건너뜀 → 중복 안 생김!
#ifndef(if not defined) / #define / #endif 세 줄이 한 세트. 매크로 이름은 보통 파일명을 대문자로 (libsbs.h → LIBSBS_H). 모든 .h에 습관처럼 붙입니다.

3부: ASCII 코드 — 문자 분류의 토대

3.1 문자는 사실 숫자다 (7차시 복습)

char는 작은 정수입니다. 각 글자에는 ASCII 코드값이 정해져 있습니다. 문자 분류 함수는 전부 "이 숫자가 어느 범위에 드나?"를 따지는 일입니다.

범위문자의미
0–31, 127제어 문자화면에 안 보임 (엔터·탭 등)
32공백 출력 가능한 첫 글자
32–126출력 가능isprint 범위
48–57'0'–'9'숫자 문자
65–90'A'–'Z'대문자
97–122'a'–'z'소문자
c >= 'a' && c <= 'z'   // 소문자 판별 (문자로 비교 = 그 코드값으로 비교)
c >= '0' && c <= '9'   // 숫자 판별
c - 32                 // 소문자 → 대문자 ('a'97 - 32 = 'A'65)
c + 32                 // 대문자 → 소문자
'a'와 'A'의 차이가 정확히 32라서 ±32로 변환됩니다. 직접 빼보면 'a' - 'A' == 32.

3.2 두 가지 약속 (꼭 기억)

약속 1 — 반환값은 "참/거짓": 분류 함수(is*)는 조건을 만족하면 0이 아닌 값(참), 아니면 0(거짓)을 돌려줍니다. 꼭 1일 필요는 없습니다. C에서 "0이 아니면 참"이기 때문입니다(3차시).

약속 2 — 매개변수가 char가 아니라 int: 표준 함수들은 int c로 받습니다. 문자 하나를 int에 담아도 되고(자동 변환), int라야 일반 문자(0~255) 외의 특수값(EOF 등)도 표현할 수 있기 때문입니다. 우리도 표준과 똑같이 int c로 받습니다.

man 3 isalpha로 표준 명세 확인(1차시 man 사용법). "참이면 0이 아닌 값, 거짓이면 0"이 핵심.

4부: 7개 함수 직접 구현

4.1 분류 함수 (is*)

모두 int를 받아 조건을 만족하면 0이 아닌 값, 아니면 0을 반환합니다. 범위 판별만 하면 됩니다.

int sbs_isalpha(int c)   // 알파벳(a-z, A-Z)이면 참
{
    return ((c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z'));
}

int sbs_isdigit(int c)   // 숫자 문자(0-9)이면 참
{
    return (c >= '0' && c <= '9');
}

int sbs_isalnum(int c)   // 알파벳 또는 숫자
{
    return (sbs_isalpha(c) || sbs_isdigit(c));
}

int sbs_isascii(int c)   // ASCII 범위(0~127)이면 참
{
    return (c >= 0 && c <= 127);
}

int sbs_isprint(int c)   // 출력 가능 문자(32~126)이면 참
{
    return (c >= 32 && c <= 126);
}

범위가 왜 이런지:

  • isascii → ASCII는 0~127로 정의된 7비트 코드. 그래서 0 <= c <= 127.
  • isprint → 화면에 보이는 글자는 32(공백)부터 126(~)까지. 127은 DEL(제어문자)이라 제외, 32 미만도 제어문자라 제외.
  • isalnum → 이미 만든 sbs_isalpha와 sbs_isdigit를 재사용. 같은 libsbs.h에 선언돼 있어 서로 호출할 수 있습니다.
작은 함수를 조합해 큰 함수를 만드는 감각이 라이브러리 설계의 핵심입니다. isalnum을 범위로 다시 쓰지 말고 두 함수를 부르세요.

4.2 변환 함수 (toupper / tolower)

대상 글자면 변환하고, 대상이 아니면 원래 값 그대로 반환합니다. 이 "그대로 반환"을 빠뜨리는 실수가 가장 많습니다.

int sbs_toupper(int c)   // 소문자면 대문자로, 아니면 그대로
{
    if (c >= 'a' && c <= 'z')
        return (c - 32);
    return (c);          // ← 숫자·기호·대문자 등은 그대로!
}

int sbs_tolower(int c)   // 대문자면 소문자로, 아니면 그대로
{
    if (c >= 'A' && c <= 'Z')
        return (c + 32);
    return (c);
}

예: sbs_toupper('a') → 'A', sbs_toupper('5') → '5'(그대로), sbs_toupper('Z') → 'Z'(이미 대문자라 그대로).

5부: 직접 해보기 (실습 흐름)

순서대로 따라 하면 됩니다.

① 헤더 작성 — libsbs.h에 인클루드 가드 + 7개 프로토타입.

② 함수마다 한 파일 — sbs_isalpha.c, sbs_isdigit.c … 각 파일 첫 줄에 #include "libsbs.h".

/* sbs_isalpha.c */
#include "libsbs.h"

int sbs_isalpha(int c)
{
    return ((c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z'));
}

③ 컴파일 확인 — 경고 없이 빌드되는지.

$ gcc -Wall -Wextra -Werror -c sbs_isalpha.c -o sbs_isalpha.o

(-c는 링크 없이 컴파일만 — 함수 단위 점검용)

④ 채점 — 아래 5부 채점 스크립트로 한 번에 검증.

흔한 에러: libsbs.h: No such file → .c와 같은 폴더에 헤더가 있는지, "libsbs.h"(따옴표)로 썼는지 확인.

6.1 파일 구조

6.3 채점 기준

1단계: gcc -Wall -Wextra -Werror 컴파일 → 경고 1개라도 있으면 그 함수 0점
2단계: 표준 함수(libc)와 0~255 전 범위 비교 → 모두 일치해야 통과

출력 예시:

=== libsbs 9차시 채점 ===
✓ sbs_isalpha   (256/256)
✓ sbs_isdigit   (256/256)
✗ sbs_toupper   (254/256)  →  -v로 상세 확인
...
결과: 6 / 7 통과
표준 함수가 정답(oracle)입니다. 정답을 외울 필요 없이, libc와 똑같이 동작하면 통과입니다. 위 예시에서 sbs_toupper가 2개 틀린 건 보통 "대상이 아닐 때 그대로 반환"(return (c);)을 빠뜨린 경우입니다.

핵심 정리

  1. #으로 시작하는 줄은 전처리기가 컴파일 전에 처리 (붙여넣기·치환)
  2. 헤더(.h)는 선언(메뉴판), 소스(.c)는 정의(주방) — 역할 분리
  3. "내 헤더" vs <남의 헤더> — 따옴표는 내 것, 꺾쇠는 시스템 것
  4. 인클루드 가드(#ifndef/#define/#endif)로 중복 포함 방지 — 두 번째부턴 건너뜀
  5. 문자는 ASCII 정수 → 범위 판별로 분류, ±32로 대소문자 변환
  6. is*는 참이면 0 아닌 값·아니면 0, 변환 함수는 대상 아니면 그대로 반환
  7. bash grade.sh로 표준 함수와 비교해 자동 채점

다음 차시 예고

10차시에서는 메모리 함수 I(sbs_memset, sbs_bzero, sbs_memcpy, sbs_memccpy)을 구현합니다. void *(범용 포인터)의 개념과 바이트 단위 복사 원리를 다루고, 오늘 만든 libsbs.h에 함수를 계속 추가합니다. 채점 스크립트도 같은 방식으로 사용합니다.

과제 1: libsbs.h 작성

libsbs.h 파일을 만들고 인클루드 가드와 7개 함수 프로토타입을 작성하세요.

요구사항:

  • 인클루드 가드 #ifndef LIBSBS_H / #define LIBSBS_H / #endif
  • 7개 함수 선언 (모두 int 반환, int c 매개변수)

작성 예시:

#ifndef LIBSBS_H
# define LIBSBS_H

int   sbs_isalpha(int c);
int   sbs_isdigit(int c);
int   sbs_isalnum(int c);
int   sbs_isascii(int c);
int   sbs_isprint(int c);
int   sbs_toupper(int c);

각 .c 파일은 첫 줄에 #include "libsbs.h"를 넣습니다.

과제 2: sbs_isalpha

sbs_isalpha.c — 알파벳(a-z, A-Z)이면 0이 아닌 값, 아니면 0.

#include "libsbs.h"

int sbs_isalpha(int c)
{
    return ((c >= 'a' && c <= 'z') || (c >= 'A' && c <= 'Z'));
}

검증: man 3 isalpha로 표준 명세 확인.

sbs_isdigit.c — 숫자 문자(0-9)이면 참.

힌트:

return (c >= '0' && c <= '9');

과제 4: sbs_isalnum

sbs_isalnum.c — 알파벳 또는 숫자이면 참. 이미 만든 함수를 재사용하세요.

힌트:

return (sbs_isalpha(c) || sbs_isdigit(c));
작은 함수를 조합하는 연습. sbs_isalpha, sbs_isdigit는 같은 헤더로 선언되어 있어 바로 호출 가능.

과제 5: sbs_isascii / sbs_isprint

sbs_isascii.c — ASCII 범위(0~127)이면 참.
sbs_isprint.c — 출력 가능 문자(32~126)이면 참.

힌트:

/* isascii */ return (c >= 0 && c <= 127);
/* isprint */ return (c >= 32 && c <= 126);
경계값 주의: 127은 ascii지만 print 아님(제어 문자 DEL). 32(공백)는 print.

과제 6: sbs_toupper / sbs_tolower

sbs_toupper.c — 소문자면 대문자로, 아니면 원래 값 그대로.
sbs_tolower.c — 대문자면 소문자로, 아니면 원래 값 그대로.

힌트:

int sbs_toupper(int c)
{
    if (c >= 'a' && c <= 'z')
        return (c - 32);
    return (c);   // 대상 아니면 그대로!
}
자주 실수: 변환 대상이 아닐 때 그대로 반환하는 return (c);를 빠뜨림. 숫자·기호도 그대로 나와야 표준과 일치.

심화 과제 (선택) — fd 출력 함수

기본 7개를 끝냈으면 advanced.md의 fd 출력 함수에 도전하세요. write 시스템 콜과 재귀를 씁니다.

  • sbs_putchar_fd(char c, int fd) — fd에 한 글자
  • sbs_putstr_fd(char *s, int fd) — fd에 문자열 (NULL 방어)
  • sbs_putnbr_fd(int n, int fd) — fd에 정수 (재귀, INT_MIN 함정 주의)

가장 어려운 부분은 sbs_putnbr_fd의 INT_MIN(-2147483648) 처리입니다. -n이 오버플로 나므로 long으로 받아야 합니다(advanced.md 참고).

보너스: 3 / 3 통과
심화는 <unistd.h>(write) 허용. 기본 7개는 여전히 <ctype.h> 금지.

  2. 표준 isalpha는 음수나 256 이상 입력에 어떻게 동작할까? (man 3 isalpha의 주의사항)
  3. 인클루드 가드가 없으면 어떤 에러가 날까? (중복 선언 — 직접 빼고 실험해보기)

void	sbs_putnbr_fd(int n, int fd)
{
	long	nb;
	char	c;

	nb = n;
	if (nb < 0)
	{
		write(fd, "-", 1);
		nb = -nb;
	}
	if (nb >= 10)
		sbs_putnbr_fd((int)(nb / 10), fd);
	c = (char)(nb % 10) + '0';
	write(fd, &c, 1);
}

void	sbs_putstr_fd(char *s, int fd)
{
	int	i;

	if (s == NULL)
		return ;
	i = 0;
	while (s[i])
	{
		write(fd, &s[i], 1);
		i++;
	}
}
