Slide 03 / Memory & Address 5차시: 포인터 기초

메모리와 주소

변수는 메모리에 산다

변수를 선언하면 메모리에 공간이 생기고, 그 공간엔 주소가 있다

주소 = 메모리의 번지수. n을 쓰면 그 주소에서 값을 꺼낸다.

이미 만난 적 있다

3차시 scanf("%d", &guess)의 &가 바로 주소 연산자.

메모리 그림 
주소        값
0x7ffe04   42   ← int n
0x7ffe08    ?
0x7ffe0c    ?

int n = 42;
// 이름 n = "42가 든 주소"

주소값은 실행할 때마다 달라질 수 있다. 중요한 건 "변수마다 고유 주소가 있다"는 사실.

Slide 04 / Address-of & 5차시: 포인터 기초

주소 연산자 &

변수 앞에 &를 붙이면 그 변수의 주소를 얻는다.

int n = 42;

printf("%d\n", n);
// 42 (값)

printf("%p\n", (void *)&n);
// 0x7ffe... (주소)

%p로 주소 출력

주소는 %p 형식으로 출력. (void *)로 캐스팅하면 경고가 사라진다.

기억할 것

n은 값, &n은 그 값이 사는 주소. 둘은 완전히 다른 것.

Slide 05 / Pointer Declaration 5차시: 포인터 기초

포인터 — 주소를 담는 변수

int n = 42;
int *p;      // int를 가리키는 포인터
p = &n;       // p에 n의 주소 저장

// 또는 한 줄로
int *p = &n;
int *p;p는 int 포인터
&nn의 주소
p = &n;p가 n을 가리킴

타입이 중요

int *는 int를, char *는 char를 가리킨다. 가리키는 타입에 따라 역참조 크기가 정해진다.

그림으로

  p          n
[0x7ffe04] → [42]

p는 n의 주소를 담고, 그 주소엔 42가 있다.

Slide 06 / Dereference * 5차시: 포인터 기초

역참조 연산자 *

포인터 앞 * = 그 주소에 있는 값. 읽기도 쓰기도 된다.

int n = 42;
int *p = &n;

printf("%d\n", *p);  // 42 읽기
*p = 100;             // 쓰기
printf("%d\n", n);   // 100!

*p와 n은 같은 메모리. 하나 바꾸면 둘 다 바뀐 듯 보인다.

`*`의 두 가지 얼굴

int *p;   // 선언: "포인터다"
*p = 5;   // 사용: "가리키는 곳에 5"

선언할 때의 *와 사용할 때의 *는 역할이 다르다. 헷갈리지 말 것.

Slide 07 / Modify Original 5차시: 포인터 기초

포인터로 원본 바꾸기 — 4차시의 한계 돌파

// 복사 — 원본 안 바뀜
void try_change(int x)
{ x = 100; }

// 주소 — 원본 바뀜!
void real_change(int *p)
{ *p = 100; }
int a = 5;

try_change(a);
printf("%d\n", a);  // 5

real_change(&a);
printf("%d\n", a);  // 100

4차시: 값 전달은 복사라 원본을 못 바꿨다. 주소를 넘기면 함수가 원본에 직접 접근한다.

Slide 08 / swap 5차시: 포인터 기초

swap — 포인터의 대표 예제

void swap(int *a, int *b)
{
    int tmp = *a;  // a의 값 보관
    *a = *b;       // b → a 자리
    *b = tmp;      // 보관값 → b 자리
}

int main(void)
{
    int x = 3, y = 7;
    swap(&x, &y);   // 주소를 넘김
    printf("%d %d\n", x, y);  // 7 3
}

값으로 넘기면 실패

swap(x, y)는 복사본만 바꿔 동작하지 않는다. 반드시 &x, &y(주소)를 넘기고 int *로 받는다.

tmp가 필요한 이유

먼저 *a = *b를 하면 a의 원래 값이 사라진다. 그래서 tmp에 미리 보관한다.

Slide 09 / NULL & Safety 5차시: 포인터 기초

포인터 안전과 NULL

위험: 초기화 안 한 포인터 
int *p;   // 쓰레기 주소
*p = 5;   // 위험! → 크래시
// segmentation fault
안전: NULL로 초기화 
int *p = NULL;  // 아무것도 안 가리킴

if (p != NULL)   // 쓰기 전 확인
    *p = 5;

libsbs malloc 계열은 실패 시 NULL 반환. NULL 체크는 10~11차시 메모리 함수의 필수 습관.

void swap(int *a, int *b)
{
    int tmp = *a;
    *a = *b;
    *b = tmp;

함정: 값을 넘기면 안 바뀐다. 반드시 &

&와 *가 헷갈려요

&는 값→주소, *는 주소→값. 반대 방향으로 기억

왜 크래시가 나요?

가리키는 곳이 없는 포인터를 역참조했을 때. NULL 체크 습관

선언의 *와 사용의 *는?

int *p는 선언, *p=5는 사용. 문법이 다르다
