# libsbs 코드 리뷰 체크리스트

동료 코드를 리뷰할 때 사용하세요. 항목별로 확인하고, 발견한 점을 코멘트로 남깁니다.

---

## 정확성 (Correctness)

- [ ] 엣지 케이스를 처리하는가? (빈 문자열 `""`, `NULL`, 길이 0, 경계값)
- [ ] 반환값이 표준 명세와 일치하는가? (`man 3 함수명`으로 확인)
- [ ] `\0` 종결을 빠뜨리지 않았는가? (문자열 생성/복사)
- [ ] 버퍼 범위를 넘지 않는가? (`i < dstsize - 1` 등)
- [ ] 부호 비교를 `unsigned char`로 하는가? (memcmp, strncmp)

## 메모리 안전 (Memory Safety)

- [ ] `malloc` 후 NULL 검사를 하는가?
- [ ] 할당한 메모리를 free하거나, 호출자 책임임을 명시하는가?
- [ ] 곱셈 오버플로를 방어하는가? (calloc)
- [ ] 읽기 전용 인자에 `const`를 붙였는가?
- [ ] `valgrind`로 누수 0을 확인했는가?

## 스타일 / 일관성 (Style)

- [ ] 들여쓰기가 일관적인가? (탭)
- [ ] 변수를 함수 상단에 선언했는가?
- [ ] 함수 이름이 `sbs_` 접두사 + snake_case인가?
- [ ] `return (값)`처럼 반환값에 괄호를 쓰는가?
- [ ] 컴파일 경고가 없는가? (`-Wall -Wextra -Werror`)

## 중복 / 재사용 (Reuse)

- [ ] 같은 로직을 반복하지 않고 작은 함수를 재사용하는가?
  - `sbs_isalnum` → `sbs_isalpha` + `sbs_isdigit`
  - `sbs_bzero` → `sbs_memset`
  - `sbs_calloc` → `sbs_memset`
  - `sbs_strlcpy/strlcat/strdup` → `sbs_strlen`
- [ ] 매직 넘버 대신 의미 있는 표현을 쓰는가? (`32` → `'a' - 'A'` 맥락)

---

## 리뷰 코멘트 작성 원칙

1. **사람이 아니라 코드를** 리뷰한다
2. **질문형**으로: "왜 이렇게 했나요?", "여기 NULL 검사가 필요할까요?"
3. **좋은 점도** 언급한다
4. **구체적으로**: 줄 번호·함수명·이유를 명시
5. 비난 대신 **제안**: "~하면 더 안전할 것 같아요"

### 예시

```
[sbs_memccpy.c]
✓ 좋아요: 정지 문자를 (unsigned char)로 캐스팅해 비교한 점이 정확해요.
? 질문: n이 0일 때도 정상 동작하나요? (루프 진입 전 확인)
→ 제안: 반환값 d + i + 1을 주석으로 설명하면 다음 사람이 이해하기 쉬울 것 같아요.
```
